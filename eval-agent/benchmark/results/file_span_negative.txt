File->span implementation (deterministic, no embedding, no whole-file dump):
  FileLexicalIndex simple hit count (distinct*10+hits) over query_terms, built from file_hashes + root reads per context call (incremental, no DB). Search ranks files by term coverage.
  For each strong file (top3, score>=max*0.35, not already covered) generate bounded query-centered spans:
    - line scores = distinct query terms per line
    - sliding windows FILE_SPAN_WINDOW=30 (and 40 tested), step10, score=sum line_scores
    - pick top window(s) per file, up to FILE_SPAN_PER_FILE=1, require >=0.5*best, non-overlapping
    - prefer enclosing real symbol when window inside single symbol, else module-level span
    - emit as synthetic Symbol File:span:start-end kind Function, role Dependency (so never displaces primaries), score=file_score*0.4, provenance lexical:file->span, per-file cap 2 files max, canonicalize overlap>0.8
  No new embedding, no PR/gold, span selection depends only on task text + base repo contents. Incremental: reads current filesystem, no persisted file table.

Forensic (phase1) showed all 6 rescue files have dense term clusters inside real symbols (inside method/function dominates, 60-line window would contain 22-30 hits and gold). So localization is feasible in principle.

Classification of failure (from forensic + experiment):
  - Wrong representative symbol: fixed by spans (no longer single __module__), but window selection still picks wrong region (tail vs dense cluster).
  - Relevant evidence outside symbol boundaries: no, evidence is inside symbols.
  - Allocator role ordering: mitigated by Dependency role (no displacement of primaries observed).
  - File score too authoritative: mitigated by limit 2 and threshold 0.35, but still adds noise for tasks where gold file not top-ranked.
  - Combination: file discovery ranking is not discriminative enough — simple hit count ranks non-gold files (variables, lint/run, fixtures) above gold (utils, plot, test_skipping) due to common term frequencies; BM25 with idf also fails (0 hits). So discovery itself is noisy, and span windowing based on distinct term hits picks highest-density window which may be comments/tail, not gold.

Overhead: query latency +15-25ms (file reads + window scoring over 5000 files, 24 terms), memory + ~0 (no persisted index), index size unchanged, incremental correct (reads current filesystem).

Conclusion: file-level lexical discovery does find 5/6 files in hybrid ranking, but deterministic within-file lexical windowing (distinct term hits, 30-40 lines, step10) does not reliably locate gold evidence — picks high-density tail/comment regions, and overall adds tokens without improving File-F1/Line-F1. No Pareto frontier move. Per acceptance, revert and document boundary: file discovery works, but deterministic localization without embedding or gold cannot identify useful spans. Keep canonical baseline (0.405 budgeted, ~1.8K tokens).
