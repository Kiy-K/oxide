# Turso gate round — raw output

Candidate: `turso` 0.7.2 (the version this round measured; the manifest asks for
"0.7", so pin it if you need byte-identical numbers).

Machine: the same laptop as the rest of this evaluation. Every database run is
on /home (btrfs, ~175 GB free), never tmpfs. Binary built with
`cargo build --release -j 2 --no-default-features --features turso` — not the
crate's default features, which install `#[global_allocator] mimalloc`.

Reproduce with:

    cargo build --release -j 2 --no-default-features --features turso
    ./target/release/sdb_gate turso        <files> <per_file> <workdir>   # gate suite
    ./target/release/sdb_gate turso-shapes <files> <per_file> <workdir>   # ingest attribution

## Ingest cost by index shape

`turso-shapes` loads the same corpus four ways and reports ms/symbol. The
executor-park counters exist because a hand-rolled `block_on` that naps on
every `Pending` would be indistinguishable from a slow engine; they read ~0 ms
over a handful of polls in every run, so the numbers below are the engine.

of 80 files of 25 — four times fewer transactions, therefore four times fewer
Tantivy commits, for identical data. (The `optimize_10` row is not comparable
