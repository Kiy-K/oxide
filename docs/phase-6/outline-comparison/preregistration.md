# Structural file outlines (Issue #44): preregistration (2026-10-19)

Question: at equal context budgets, does a compact structural file outline help an
agent, or OXIDE's packer, choose and read more useful evidence than OXIDE's current
file-level view, without losing source-backed context or worsening indexing and query
cost? Three arms:

- **A (control):** current behavior, unchanged. A file entity's view is its
  module-level source runs (`packing.module_regions`); a `paths`-hinted file shows its
  header view (first run, normally the imports). Retrieval `oxide-retrieval-v2`, router
  `oxide-router-bfs-v2`, selector `oxide-select-greedy-v4`, payload `oxide-payload-v3`.
- **B (upstream outline):** `ast-grep outline --stdin --items all --json=compact
  --lang L` from the pinned **ast-grep-cli 0.51.0** (binary sha256 `bd9e2029…1e24`,
  checked before every run), over the **captured snapshot bytes** read through
  `View.source`, never the worktree. Normalized into an experiment-only type
  (`scripts/outline.py`). Never run by production code.
- **C (native outline):** the same entry contract rendered from OXIDE's
  already-indexed facts, with no parse: a file's `contains` children (items), their
  `contains` children (members), indexed signatures, and the file's `imports`
  relations with their evidence ranges. Reading a line of the captured bytes to number
  it is allowed; parsing is not.

This section, the scripts in `scripts/`, the outline contract and renderer, and the
conformance gold in `conformance/` are committed before any B or C result is computed.
Results are appended to `README.md` later and do not edit this file.

## What was seen before the freeze (disclosed)

- **Tool discovery:** `outline --help`, and B's and C's renderings of one 26-line
  probe file (decorators, nested defs, overloads, a parenthesized multi-line import).
  B dropped the multi-line `from a import (b, c)`, gave no Python member signatures,
  excluded decorators from ranges and reported a `def` under `if` as a top-level item.
  C included decorators, nested defs and overloads (`o`, `o~1`, `o~2`) but no class
  fields. One JSX probe: ast-grep's JavaScript grammar ends `<div class="x"/>` early.
- **Harness smoke:** `context_run.py` on the seven Python fixture tasks, mechanics only
  (files written, outline items packed, pointers computed). No metric was read.
- **Arm A only:** `context_run.py` with `ARMS=A` on Python and TypeScript dev, and the
  navigation arms N, A and F on dev (below). These set the reference values.
- **Agent switches:** N, A and F were first run on Python dev (and part of TypeScript)
  with Claude Code / `claude-sonnet-5-5` (Python A recall@4096 0.800 and 0.791 over two
  repetitions, N 0.782 and 0.781, F 0.400), then partly with OpenCode's free
  `opencode/beam-free` (stock agent with permission-gated tools; abandoned for rate
  limits after 162 calls, 51 rate-limited; its code-mode `execute` tool once ran
  despite `ask`). At the user's direction the agent became OpenCode with
  `openai/gpt-6-luna`, before any B or C call. The earlier runs are kept in the data
  directory and not used; beyond one graded smoke call, no beam-free metric was read.
- **Online research** ([research.md](research.md)): Agentless's skeleton beat complete
  files for element localization (58.3 % vs 53.7 % contains-GT, $0.02 vs $0.15);
  skeletons gave no resolve gain over dropping context once localization is fixed
  (arXiv 2607.09691, N = 70, p = 0.75, ~9 % run-to-run flips); upstream ast-grep's own
  forced-use agent benchmark reported 35–55 % lower cost on large repositories and none
  or higher cost on small ones, with answers at ceiling in both arms.

## Outline contract (both arms, one renderer)

Entries: imports, top-level items and their direct members, each with a byte range in
the captured file, 1-based first/last lines, a kind and a label (the first line of the
signature, else the name; at most 120 characters). Rendering, shared by B and C:

    ### <path> (<n> lines) outline
    L<first>-<last> <kind>: <label>
      L<first>-<last> <kind>: <label>        (members)

B's labels are ast-grep's `signature`; C's are OXIDE's indexed signature. C's imports
are one entry per maximal run of consecutive lines holding import evidence, labelled
with the imported names, because OXIDE keeps no import-statement range. Fields OXIDE
cannot reproduce are reported, not faked: `isExported`/`isPublic` flags, `astKind`,
statement-level import ranges, class fields of Python classes and other unmodeled
declarations. A file whose outline fails or is empty has no outline (B: "outline
unavailable").

## Stage 1: extraction (B vs C, independent of relevance)

- **Conformance gold** (`conformance/`, hand-written from the languages, not from
  either tool): Python (decorators, async, nested defs, overloads, multi-line and
  aliased imports, class fields, conditional defs, non-ASCII names), TypeScript
  (imports/exports, overloads, interfaces, enums, abstract classes, namespaces, ambient
  modules, default exports, re-exports), TSX, CommonJS JavaScript (private fields,
  `module.exports`) and JSX with `class=`/`for=` attributes. Required and optional
  entries; recall over required ones; every unmatched entry is listed.
- **Real corpora:** every parsed source of the Python fixture, requests
  (`psf__requests@22623bd8c265`), flask, seaborn; the TypeScript fixture, code-server
  (`78658f1cf48a`), darkreader (`a787eb511f45`); the JavaScript fixture, Preact
  `630a87e4` and Express `0dee2c52` (the javascript-v1 pins). The navigation case files
  add the vscode/MUI/vue candidate files.
- **Measures:** B-vs-C matching (by name and overlapping range) with a cause class for
  every disagreement (`B only`/`C only` by role and kind, hierarchy, start or range
  differs), import-line agreement, provenance (range inside the file; the name inside
  its range), determinism (two runs byte-identical), failures, per-file wall time,
  ast-grep peak RSS, rendered units against the whole file and A's file view.

## Stage 2: navigation (the primary question)

Each task with verified gold in an indexed file gives one case: the task's issue text,
and as candidates its verified gold files plus the first three non-gold files in
production search order (`repo.search`), sorted by path so position does not reveal
gold. Arms differ only in each file's overview:

- **N** path and line count only (floor);
- **A** path, line count and the production hinted-file view (`outline.header_view`);
- **F** the whole file, every line numbered (Agentless's baseline; cost reference);
- **B** / **C** path, line count and the outline.

Agent: OpenCode 2.0.32, `opencode run --standalone --model openai/gpt-6-luna --agent
nav`, one turn, the fixed prompt in `scripts/nav.py` on stdin. The `nav` agent's system
prompt is `SYSTEM` and it has no tools (all disabled and denied; asked to list its
tools, it answers none); the config is isolated (no MCP, plugins, instructions or
Claude Code compatibility, written by `nav.configure()`) and the working directory is
empty. A call in which any tool completed would be invalid (scored 0, counted under V).
OpenCode reports no token counts or cost for this provider, so cost is not measured.

- **Primary metric:** gold-line recall at T = 4,096 units, mean over repetitions per
  task, macro over tasks. A failed or unparseable call scores 0.
- Reported, not gated: T = 2,048; unlimited recall (decision quality alone); gold file
  hit; read precision; overview and read units; cost.
- Repetitions: dev 2 (N, A, B, C), held-out 1; F once on dev only (its prompts are up
  to ~200k units; at T = 4,096 it can read nothing by construction).
- Dev: ContextBench-py `baseline-v1` dev (15 tasks) and ContextBench-ts dev (25 with verified gold).
  Held-out: py xarray + pytest (29 tasks with verified gold), ts MUI + vue core (56). Held-out runs once, after
  dev, with nothing changed.

## Stage 3: final context at equal budgets (payload)

`scripts/context_run.py` runs the frozen ContextBench scorers with production
retrieval, routing, values, floor, item cap and order in every arm; only what a file
entity shows changes. Arms A, **A0** (file entities get no view: the control for the
budget an outline frees), B and C (the file's view is its outline, packed as an item
at the pseudo-path `outline:<path>`, lines (0, 0), so it spends units but can never
count as gold source). Conditions **U** (task hints) and **H** (plus the verified gold
files as `paths`, where a hinted file currently shows its header view). Metrics: the
frozen verified-gold `line_recall`, `span_recall`, `file_recall` at 256/1,024/4,096,
entry recall and routed coverage, plus `pointer_recall` (a packed outline has an entry
intersecting the span) reported apart from source coverage. Dev only, unless P passes.

## Criteria (thresholds fixed against measured A)

Measured A, dev (filled from the pre-freeze runs, `results/prefreeze/`):

| gold-line recall (macro over tasks, mean of r1 and r2) | A py (15) | A ts (25) | A pooled (40) | N pooled | F pooled (r1) |
|---|---|---|---|---|---|
| @4,096 | 0.627 | 0.474 | 0.531 | 0.544 | 0.300 |
| @2,048 | 0.491 | 0.347 | 0.401 | 0.512 | 0.172 |
| unlimited | 0.658 | 0.544 | 0.587 | 0.544 | 0.609 |
| gold file hit | 0.850 | 0.855 | 0.853 | 0.805 | 0.856 |

A's repetition noise (mean per-task |r1 − r2| of recall@4,096): **0.106** (N: 0.050).
So N4 requires a dev gain > 0.212. 205 calls, no failures, no tool use. Already at
these values N (paths and lengths only) is at least as good as A at both budgets: A's
view costs a median 1,516 units of overview (N 86, F 17,323) and buys unlimited-budget
recall (+0.04) that the paid overview then gives back. Gold file hit is high in every
arm (0.81–0.86), so the room left is mostly *where in the file* to read.

Per outline arm X in {B, C}:

- **N1** dev pooled `recall@4096` X − A ≥ +0.10, and X ≥ A on each benchmark.
- **N2** held-out pooled X − A ≥ +0.05, and X ≥ A − 0.02 on each benchmark.
- **N3** dev breadth: at least 3 tasks gain > 0.10, and gaining tasks ≥ 2 × tasks losing
  > 0.10.
- **N4** dev gain > 2 × A's mean per-task |r1 − r2| (its repetition noise).
- **N5** `recall@2048` X − A ≥ −0.05 on dev and held-out (an outline must not lose at a
  tighter budget).
- **V** technical failures ≤ 10 % of X's calls.
- **E1** conformance recall of required entries ≥ 0.90. **E2** every range inside its
  file; name inside range for ≥ 99 % of named entries. **E3** deterministic on every
  file. **E4** failures ≤ 1 % of parsed files.
- **O (C)** per-file outline p95 ≤ 50 ms; `build_context` median with C ≤ 1.25 × A.
  **O (B)** per-file p95 ≤ 100 ms; context median ≤ 1.25 × A; ast-grep peak RSS ≤
  256 MB; wheels for the four CI platforms (Linux x86_64, Windows x86_64, macOS x86_64
  and arm64; checked from PyPI metadata, runtime on Linux only).
- **P (payload, separate)** on dev, some condition/budget (1,024 or 4,096) gains
  > 0.02 `line_recall` over A, none loses > 0.02, and the gain exceeds A0's by > 0.02.
- **Invariants** (must hold or the run is invalid): A.U reproduces the frozen
  `baseline-v9`/`typescript-v6` compat hashes on every task; entries and routing are
  identical across arms within a condition.

## Verdict

- An arm **passes** when N1–N5, V, E1–E4 and its O criteria hold. P only decides
  whether the outline also belongs in the payload; it cannot make an arm pass.
- **PASS** if an arm passes. If both do, recommend C unless B's held-out gain exceeds
  C's by ≥ 0.05.
- **REJECT** if no arm reaches a dev gain of +0.05, or every arm that does has a
  held-out gain ≤ 0.
- **INCONCLUSIVE** otherwise (for example a dev gain that held-out does not confirm,
  gains inside the noise or carried by fewer than 3 tasks, or failures over 10 %).

Whatever the verdict, A stays production behavior in this milestone; a PASS leads to
a separate implementation issue, not a production change here.

## Attribution rules

Entries and routing are identical across arms by construction (checked), so no
navigation or payload difference is a retrieval or routing effect. In the payload, an
outline's effect is X − A0 (A0 frees the same budget with no outline); X − A mixes it
with losing module-level source. In navigation, the arms differ only in the overview
text; N is the floor and F the ceiling of what more structure could buy.
