# Phase 6 Python context-quality baseline v2 (`contextbench-py-v2`)

A scorer correction of [`baseline-v1`](../baseline-v1/README.md), with **the engine
unchanged**: every task's entry order, routed set, payload digests and bundle
diagnostics equal v1's (measured), so every metric difference below is the scorer.
v1 stays as frozen; this directory supersedes it as the gate of `mise run verify`.
Tasks, corpora, splits, budgets, tolerance and gated metric names are v1's. The
held-out results had already been read when this was written, so they were used to
find scorer and gold defects, never to choose retrieval, routing or packing behavior.

## What changed (scorer `contextbench-py-scorer-v2`)

1. **Gold audit.** Every annotated ContextBench span is checked once against its own
   annotated `content` at the pinned corpus, recorded in
   [`gold-audit.json`](gold-audit.json) (`contextbench-py-gold-audit-v1`, generated by
   `contextbench.py audit PARQUET`, reproducible byte for byte). The annotations
   themselves stay as built in `baseline-v1/tasks.json` (rebuilt from the parquet: byte
   identical). Spans are split into **verified** gold, which the metrics and the gate
   use, and **unverified** gold, which is scored and reported separately, never
   dropped. Fixture gold is `ast`-derived and verified by construction.
2. **Gold lines are non-blank lines.** v1 counted every line of a span. A symbol's
   source ends at its last token, so the blank lines between two declarations are in
   no source view, and a span over adjacent declarations could never be `complete`
   (all 27 partial spans at 4096 in v1 contain blank lines). Annotated content already
   ignores blank lines.
3. **Module-level gold is coverable by definition.** v1 let only symbol entities cover
   gold, so imports, constants and top-level statements could never count as retrieved
   or routed. Now a file entity covers a span through the span's module-level lines:
   lines outside every outermost `def`/`class` (decorators included; a declaration
   nested in `if`/`try` is still outermost), found with Python's own `ast`, not OXIDE's
   parser. Symbols cover by sharing a code line.
4. **Loss stages.** Every incomplete span gets one stage per budget, the most upstream
   one among its missing lines. The unit that would carry a line is its file's
   module-level view (module-level lines) or the innermost routed symbol containing it.
   - `entry`: no routed unit, and no entry point in the span's file;
   - `routing`: no routed unit, but an entry point in the file;
   - `unsupported`: the unit was routed but the packer has no view of it (`container`);
   - `selection`: the floor, the item cap or the 64-node graph limit dropped the unit;
   - `budget`: the unit was omitted for budget or packed only as a reduced view.

   Invalid or unresolved gold is the separate unverified block, not a stage.
5. **One denominator per gold set.** Entry, routed, span, line and file recall all use
   the same set (verified, or unverified), the corrected paths and the same corpus
   revision. Aggregates report tasks, spans, distinct lines and files per split.
6. **Lines split on `\n` only.** v1's verification split corpus text with
   `str.splitlines()` (form feeds, ` `, …) while spans were counted by `\n`. No
   gold file contains such a character (measured), so this was latent; it is fixed with
   a regression case.

The gate (`test_contextbench.py`) applies v1's rules to the verified block: each gated
metric at or above its frozen value minus 0.02 per split, the verified task and span
counts unchanged, and every unverified span reported with its class in every run.

## Gold audit (208 ContextBench spans)

Rules, first match wins. `...` lines in annotated content are the annotators' elision
marks and only matter for `contained`. A span is never moved to other lines.

| Class | Rule | Verified | Spans |
| --- | --- | :---: | ---: |
| `exact` | the range's code lines equal the content's | yes | 164 |
| `contained` | the content's lines occur in order within the range (gaps allowed) | yes | 10 |
| `path` | the file is not in the corpus; exactly one path suffix of it is, holding the content at the same lines | yes, path corrected | 2 |
| `range` | the content occurs verbatim at other lines of the file | no | 12 |
| `revision` | the content is the file after the task's reference patch | no | 4 |
| `drift` | some content lines exist nowhere in the file | no | 10 |
| `empty` | no annotated content | no | 5 |
| `unresolved` | none of the above | no | 1 |

Against the categories of the correctness review:

- **Wrong source revision or path (6).** `path` (2, corrected with provenance):
  seaborn-3069 `seaborn/tests/test_distributions.py` and requests-5414
  `requests/tests/test_requests.py` are `tests/…` at those commits, holding the
  annotated content at the annotated lines. `revision` (4): xarray-4629 `merge.py`,
  xarray-4966 `coding/variables.py`, pytest-10051 `logging.py` ×2 hold the patched file.
- **Line/offset mapping errors (12, all in the annotations).** `range`: the content is
  verbatim at base, at lines the range disagrees with (end short by 1–40 lines, or start
  ±1: flask-5014, requests-1142, requests-1766, xarray-4687, -7233, -7393,
  pytest-10051, -10081 ×2, -5809, -7490, -7571). No single convention explains the
  offsets, and the harness's 1-based mapping reproduces 164 spans exactly; the only
  harness-side mapping defect (6. above) affected no span. Kept as annotated and
  unverified; `gold-audit.json` records where the content is.
- **Annotation drift or invalid gold (10).** `drift`: xarray-3095, -3993 ×2, -4695 ×2,
  pytest-10356, and pytest-5787 ×4 (content of a much later pytest, ranges in
  120/220-line blocks past the end of `reports.py`).
- **Valid source, overly strict rule (10).** `contained`: v1 demanded equality, but the
  annotated content elides with `...` (xarray-6461 skips 57 docstring lines), drops
  doctest `<BLANKLINE>` lines (xarray-6744 ×2) or a 7-line helper (xarray-2905), or the
  range holds 1–3 lines beyond its content: a decorator, a statement or a closing `)`
  (flask-5014 ×2, requests-2931 ×2), or neighbouring lines at its ends (pytest-5631,
  -5809).
- **Unresolved (6).** `empty` (5, all xarray-3095, round ranges such as 680–820) and
  `unresolved` xarray-6599 (content lines present, not in this order; its signature has
  annotations absent at base).

## Reproduction

```bash
mise run bootstrap                                   # corpora, FTS extension
uv run python tests/python/contextbench.py run --out /tmp/cb   # results/metrics/manifest
uv run pytest tests/python/test_contextbench.py      # the gate and the scorer cases
uv run --with pyarrow python tests/python/contextbench.py audit <full.parquet>
```

## Limitations

- v1's limits stand: 44 tasks, 5 real repositories, Python only, a regression floor
  rather than a generalization estimate, `*.py`-only corpora, no downstream-agent result.
- The audit checks that a range holds its annotated content at the pinned revision, not
  that the content is the right context for the task. A `contained` range can be wider
  than its content; ranges are scored as annotated.
- Unverified gold is 15 % of ContextBench spans and concentrated in held-out (29 of 32),
  so the verified held-out block is smaller than v1's all-gold one.
