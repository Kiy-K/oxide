# Secure paired agent evaluation harness — design

Date: 2026-11-08. Status: implemented design (PR #52).

## Intent

OXIDE's value claim is that a coding agent solves more real tasks with `oxide mcp` than without it.
Retrieval baselines cannot show that. `scripts/agent_eval` runs a paired experiment: the same
SWE-bench-style tasks, the same agent, with and without OXIDE, scored by the tasks' own hidden tests.
The harness executes untrusted agent output and untrusted task build hooks, so confinement and
scoring integrity are the requirements, not conveniences.

## Goals

- Paired arms (`base`, `oxide`) over a fixed manifest of task x arm x repetition; the held-out split is
  generated by `heldout.py` and is never edited after the first look.
- The agent, its post-run `git` inspection, the editable install and the hidden tests all run under
  bubblewrap: host mounted read-only, credential and runtime-socket paths hidden (`/run`, `/var/run`
  masked, name-service files re-bound), only the per-run work dir (and venv) writable. Missing
  bubblewrap is a hard error, never an unconfined fallback.
- The agent receives a clean environment; copied credentials are cleaned up after normal runs and
  known literal values are redacted from event output. This does not prevent a network-enabled
  agent from copying or transmitting credentials; retained traces must be treated as sensitive.
- Scoring distinguishes agent results from infrastructure failures. On the agent's tree a hang,
  a broken collection or a broken `conftest.py` are unresolved results; only a failed bubblewrap
  launch raises `TestRunError` and is recorded as a harness error, excluded from both arms. Gold
  patch verification stays strict. A missing expected test id counts as failed.
- `report` withholds a final verdict unless every planned task x arm x repetition recorded in
  `<results>.manifest.json` is scored; otherwise it prints `provisional` or `invalid`.
- A projected total token-spend threshold; resuming counts recorded spend. This is not a hard
  provider-enforced budget or a per-run token cap.

## Non-goals

No changes to `oxide` runtime, the frozen `fixtures/eval/structural-v1/` oracle, or `verify`.
No committed held-out tasks (generated locally). No Windows/macOS agent runs: the harness requires
Linux bubblewrap; tests that exercise runner logic stub confinement so platform CI still covers them.

## Files

`scripts/agent_eval/`: `confine.py` (bubblewrap argv), `run.py`/`arms.py`/`session.py`/`codex.py`/
`events.py`/`batch.py` (runner), `tasks.py` (task load, apply, tests, `TestRunError`), `report.py`,
`protocol.py`, `heldout.py`, `diagnose.py`. Tests: `tests/python/test_agent_*.py`. Data and protocol:
`fixtures/eval/agent-swe/`.

## Residual risks

- Sockets outside `/run` and `/var/run` (for example `/tmp/.X11-unix`) and network access remain
  reachable; a build hook can still use the network (needed for installs).
- A host using systemd-resolved without a fallback resolver may lose DNS inside the sandbox.
- `report` detects an incomplete matrix by count and hash, not task ids; a same-size substituted task
  set is not detected.
- Nothing here has run end to end on a real agent; protocol numbers are unmeasured until it does.

## Verification

Unit tests with a real-bubblewrap subset (skipped when absent), including a planted git clean-filter
escape test with an unconfined control, and `mise run verify`.
