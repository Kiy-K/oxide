# Phase 2B Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development; no commits or pushes.

**Goal:** Capture, derive Python knowledge, safely publish a real graph generation and reopen the same knowledge.
**Architecture:** Keep domain policy and validation in the dependency-free kernel. Runtime owns parser substrate, capture, retained source, LadybugDB resources and atomic publication; no service transport changes.
**Tech Stack:** Rust, lbug =0.21.2/native v0.21.2 compat/storage 47, ignore, tree-sitter-python, Bun/Mise.
**Spec:** docs/spec/SPEC.md, docs/BOOTSTRAP.md, accepted ADR-0002 and ADR-0010, and the user's Phase 2B requirements.

## Global Constraints

- Linux x86_64 only; macOS, Windows and network filesystems unverified.
- No Phase 3, incremental indexing, Git execution or repository code execution.
- Native artifacts SHA-256 checked, pinned, explicitly prepared, controlled and cacheable.
- Source hydration returns digest-verified retained captured bytes.
- RepoId random and persisted; all state outside the source repository in Linux XDG application data.
- Preserve kernel dependency/I/O boundary and service v1; no Ladybug native types outside storage.
- No commits/pushes. Preserve accepted ADR substance, document implementation details separately.

## Review Focus

- Corrupt CURRENT fails closed rather than selecting another generation.
- Read views retain ownership locks after store close.
- Dangling relation endpoints cannot silently disappear during database writes.
- Ignore rule changes during capture cause bounded retry.
- Python shadowing and dynamic lookup must not fabricate resolution.
